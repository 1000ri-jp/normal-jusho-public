# AI Agent / LLM / OCR 向けガイド

Jusho は、AI Agent、MCP クライアント、OCR 後処理、音声入力、SaaS の入力フォームから来る日本語住所を正規化するための API です。

LLM に住所を「それっぽく補正」させるのではなく、住所らしい文字列を抽出したあと、Jusho に渡して正規化・構造化する使い方を推奨します。

## なぜ住所専用ツールが必要か

日本の住所は、次のような揺れが頻繁に発生します。

- 全角数字、半角数字、漢数字の混在
- `1-2-3`、`1丁目2番3号`、`一丁目二番三号` のような番地表記の違い
- `ヶ`、`ケ`、`が` などの表記ゆれ
- OCR由来の `二` と `ニ`、`一` と `1` の誤認識
- 半角ハイフン、全角ハイフン、長音記号、マイナス記号などの区切り文字混在
- 都道府県や市区名が省略された住所
- 郵便番号が住所文字列に混ざった入力
- フォーム自動入力で必要になる郵便住所表記への変換
- 京都の通り名、札幌の条丁目、北海道の線・号など地域固有の表記
- 事業所名や大規模ビル名だけで住所・郵便番号が決まるケース
- 事業所名や支店名に都道府県名・市区町村名が含まれるケース
- 府中市、伊達市のような同名市区町村

LLM は自然な住所表記を生成できますが、住所マスタとの照合、どこまで同定できたかの粒度、未解決部分の扱いまでは保証しません。

業務システムに保存する前に、住所専用 API で正規化する方が安全です。

## 推奨アーキテクチャ

```text
ユーザー入力 / OCR / 音声入力 / 画像
  -> LLM が住所候補を抽出
  -> Jusho が住所を正規化・構造化
  -> CRM / 配送 / 請求 / 物件DB / SaaS に保存
```

LLM には「住所候補の抽出」を任せ、Jusho には「住所の正規化・構造化・照合」を任せます。

## REST API で使う

```bash
curl -G "https://api.jusho.dev/normalize" \
  --data-urlencode "address=東京都渋谷区渋谷２ー２１ー１"
```

複数件をまとめて処理する場合:

```bash
curl -X POST "https://api.jusho.dev/normalize/batch" \
  -H "Content-Type: application/json" \
  -d '{
    "addresses": [
      "東京都渋谷区渋谷２ー２１ー１",
      "京都市中京区御幸町通二条下る山本町"
    ]
  }'
```

## MCP で使う

MCP 対応クライアントでは、以下を設定します。

```json
{
  "mcpServers": {
    "jusho": {
      "url": "https://api.jusho.dev/mcp"
    }
  }
}
```

AI Agent には、住所を推測して書き換えるのではなく、`normalize_address` ツールを呼ぶように指示します。

```text
名刺画像から住所を抽出し、Jusho の normalize_address で正規化してから CRM に登録してください。
正規化できない場合は、元の住所文字列を残して人間確認に回してください。
```

詳細は [MCP連携ガイド](mcp-integration.md) を参照してください。

## OCR 後処理で使う

OCR では、数字や区切り文字が揺れやすくなります。

```text
東京都渋谷区渋谷２ー２１ー１
東京都渋谷区渋谷2-21-1
東京都渋谷区渋谷二丁目二十一番一号
東京都渋谷区渋谷ニ丁目21-1
```

OCRでは、漢数字の `二` がカタカナの `ニ` として読まれたり、ハイフンに見える文字が半角ハイフン、全角ハイフン、長音記号、マイナス記号として混ざったりします。

OCR 結果をそのまま保存せず、Jusho で正規化した結果を保存してください。

保存時は、正規化済み住所だけでなく、元の入力文字列も保持すると、失敗時の確認や再処理がしやすくなります。

## 人間入力で起きやすいこと

人間が入力した住所では、住所の一部が省略されたり、別の手がかりが混ざったりします。

```text
渋谷区渋谷2-21-1
丸の内1-9-1
〒150-0002 渋谷区渋谷2-21-1
府中市宮西町2-24
伊達市保原町...
```

都道府県がない、市区名すらない、郵便番号だけが追加されている、同じ市名が複数都道府県に存在する、といったケースがあります。

また、事業所名や支店名に都道府県名・市区町村名が含まれることもあります。住所本文なのか組織名の一部なのかが曖昧な場合は、元の入力文字列を保持し、正規化結果だけで上書きしない設計にしてください。

## フォーム自動入力で起きやすいこと

住所フォームや配送システムでは、日本郵便の住所表記を前提にしたマスタが使われていることがあります。

たとえば、`袖ケ浦市` と `袖ヶ浦市` のように、郵便住所として期待される表記と、国土交通省系データの表記がずれるケースがあります。

```text
入力住所
  -> 住所として同定する
  -> 国土交通省系の表記に正規化する
  -> 必要に応じて日本郵便系の住所表記へ変換する
  -> 送信先フォームや配送システムに渡す
```

フォーム側が選択肢マスタと完全一致で検証している場合、住所としては正しくても表記が違うだけで弾かれることがあります。

## 保存前のチェックポイント

- 元の入力文字列を保存しているか
- 正規化済み住所を保存しているか
- 都道府県、市区町村、町域、番地、号を分けて保存しているか
- 送信先が郵便住所表記を期待している場合、その表記へ変換しているか
- 郵便番号、行政コード、緯度経度が必要な場合は保存しているか
- 正規化できなかったケースを人間確認に回せるか
- AI Agent が住所を勝手に補完して保存しない設計になっているか
